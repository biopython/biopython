AI Policy
==========
"AI" herein refers to generative AI tools such as large language models (LLMs) 
that can generate, edit, and review software code, create and manipulate images, or generate human-like communication.

Motivation
===========
Biopython serves a large community of computational biologists, and as an open-source project, welcomes contributions from community members. With the
advent of generative AI tools used to write and submit code, we have found it necessary to detail rules that govern the use of AI tools in contributions. 
There are several reasons for this policy: (1) preserve code quality, utility, and safety; (2) avoid copyright and license infringements;
(3) prevent superfluous contributions by AI agents that may be useless or harmful, and in any case take up unnecessary time and resources from Biopython
developers.

Responsibility
==============
You are responsible for any code you submit to Biopython's repositories, regardless of whether 
it was manually written or generated by AI. You must understand and be able to explain the code you submit as well as
the existing related code. It is not acceptable to submit a patch that you cannot understand and explain yourself. 
In explaining your contribution, do not use AI to automatically generate comments, pull request descriptions, 
or issue descriptions. See below for our policy on AI translation systems.

Disclosure
==========
You must disclose if AI has been used to assist in the development of your pull request. 
If so, you must document which tool(s) have been used, how they were used, and specify what code or text is AI generated.
Biopython developers will reject any pull request that does not include the disclosure.

Code Quality
============
Contributors are expected to submit code that meets Biopython's standards. We will reject pull requests that we deem to be "AI slop". 
Do not waste developers' time by submitting code that is fully or mostly generated by AI, and doesn’t meet our standards.

Code Documentation
==================
All code must be well-documented, without the use of AI. This is not only to make the code legible and modifiable by future developers, but also to ensure that you understand what you are contributing.

Copyright
=========
In your git commit and/or pull request, please explicitly state that you agree to your contributions being dual licensed under both our original 
"Biopython License Agreement" and the more widely used "3-Clause BSD License" (see our LICENSE file for more details). That means you must own the copyright 
of any code submitted to Biopython or must include the BSD 3-clause compatible open source license(s) 
associated with the submitted code in the patch. Code generated by AI may infringe on copyright, and it is the submitter’s responsibility not to infringe. 
We reserve the right to reject any pull requests, AI-generated or not, where the copyright is in question. See our CONTRIB.rst file for more details on how to contribute, and the CONTRIBUTION wiki page on general, non-AI-related contribution policies. 

Communication
=============
When interacting with developers (forums, discussions, issues, pull requests, etc.), do not use AI to speak for you, 
except for translation or grammar editing. If the developers want to chat with a chatbot, they can do so themselves. 
Human-to-human communication is essential for an open source community to thrive.

AI Agents
==========
Using an AI agent to write code and autonomously submit a pull request is not permitted. 
A human must check any generated code and submit a pull request according to the "Responsibility" section above.
